# Public-data External Validation Protocol v2

This is a new, versioned supplementary external-validation protocol. It does not revise, overwrite, or retroactively re-adjudicate Public-data Validation v1. In particular, the frozen Boreas v1 conclusions remain `R02=FAIL`, `R10=PARTIAL`, and `BOREAS_STAGE1_READY=false` under the stricter v1 Stage-1 implementation.

## Role and authorization boundary

- `role = SUPPLEMENTARY_EXTERNAL_GENERALIZATION`
- `primary_metrological_evidence = false`
- `public_dataset_count_required = 1`
- `selected_dataset = Boreas`
- `PUBLIC_DATA_V2_RUN_AUTHORIZED = false`
- `REAL_REGISTRATION_AUTHORIZED = false`
- `REAL_DATA_MAIN_EXPERIMENT_AUTHORIZED = false`
- `MEASUREMENT_PAPER_MAINLINE_AUTHORIZED = false`

The purpose is limited to checking whether a public, independent-acquisition mobile LiDAR dataset with a fixed global reference frame shows additional scan-to-map registration updates from reference-pose initialization, geometry dependence, cross-backend trends, and correspondence reassociation that are directionally consistent with the controlled synthetic experiment.

It does not provide millimetre-scale real truth, the Measurement paper's primary real experiment, proof that an observed effect exceeds every reference-uncertainty component, or authorization for the Measurement mainline. A future Mid-360 static real experiment remains responsible for the primary real metrological evidence.

## E02: versioned reference-independence clarification

The trajectory and extrinsic have different provenance roles.

The trajectory backbone must be independent of the query-to-target registration evaluated by this experiment. It must not be generated by ICP, scan matching, LiDAR odometry, or SLAM.

A LiDAR-to-navigation static extrinsic that was already public and fixed before this experiment, and is byte-identical across evaluated sequences, may have used LiDAR data during its historical calibration only if every condition below holds:

1. It is not re-estimated in this experiment.
2. It is not re-estimated for the primary pair or either reserve pair.
3. It is not re-estimated from weak/rich labels.
4. It is not re-estimated from Open3D or PCL results.
5. It does not use any query-to-target registration output from this experiment.
6. Every evaluated sequence uses the same frozen byte-identical matrix.
7. Its complete LiDAR-assisted calibration provenance is disclosed.
8. Unknown calibration session, calibration date, or query participation remains `UNKNOWN`.
9. If extrinsic uncertainty is unknown, no absolute metrological conclusion below reference uncertainty is allowed.
10. It is used only for external trend/generalization validation.

When all requirements are evidenced, E02 may be adjudicated `PASS_WITH_DOCUMENTED_LIMITATION`. That status does not mean the extrinsic is fully non-LiDAR, independent of all historical LiDAR, or uncertainty-free. Any unmet condition makes the permission unavailable and can make E02 `FAIL`.

## E10–E11 metrology boundary

Every known uncertainty value is reported with its actual meaning and units. Orientation, synchronization, extrinsic, interpolation, deskew, or map-accumulation uncertainty that is not numerically established remains `UNKNOWN`; it is never imputed as zero.

If an observed update is smaller than or comparable to reference uncertainty, it can describe solver behavior but cannot be interpreted as a physical positioning error independently resolved by truth. Primary external conclusions are restricted to geometry trends, cross-backend ordering, and reassociation association. The Mid-360 static experiment remains necessary for the Measurement paper's primary metrological conclusion.

## Frozen future analysis contract

The normative machine-readable analysis contract is `public_data_external_validation_analysis_contract_v2.json`.

- `V2-H1`: initialize with `T0 = T_reference` and report the additional `T_est != T_reference` update as continuous translation and rotation displacement, q50/q75/q95, and per-backend solver/nonfinite counts. No millimetre physical-truth assertion is set.
- `V2-H2`: compare weak with rich geometry separately for Open3D and PCL. The directional criterion is median weak > median rich. Report the weak-minus-rich median difference, weak/rich median ratio, and 95% confidence interval using a clustered bootstrap whose block is the frozen scene interval. Snapshot-level naive bootstrap is forbidden.
- `V2-H3`: rank displacement at the frozen scene-interval level across Open3D and PCL, report Spearman rho, and use the preregistered reference threshold `rho >= 0.70`.
- `V2-H4`: reuse the frozen offline common-association definition and report pooled Spearman, scene-centered Spearman, and interval-held-out direction consistency. Reference thresholds are pooled `rho >= 0.40` and scene-centered `rho >= 0.20`. These are external-consistency criteria, not causal proof.
- `V2-H5`: report update magnitude relative to known RMSE/bounds and list every `UNKNOWN` component. An uncertainty-normalized result that cannot be computed is `NOT_COMPUTABLE`; unknowns cannot be set to zero to manufacture a normalized effect.
- `V2-H6`: Boreas v2 alone cannot set `MEASUREMENT_PAPER_MAINLINE_AUTHORIZED=true` regardless of the observed result.

## GT-only directed-pair contract

The normative machine-readable selection contract is `public_data_external_validation_pair_selection_contract_v2.json`. Overlap is computed only after E02 is not `FAIL`, fixed `ENU_ref` remains `PASS`, and E05 is `PASS` or `PASS_WITH_DOCUMENTED_LIMITATION`.

Only the gap-aware implementation at `src/phase_a_harness/real_data_preparation/stage1_gt_overlap.py` is permitted. Its file SHA-256 is `c757e576f600ddf0ea4a0111137ee43d839611267a06631359823907fcb7ac42`. The older non-gap-aware overlap implementation is forbidden.

The input inventory consists of 31 public-GT sequences. Two sequences with native gaps above 0.20 s are excluded, leaving 29 eligible reference sequences. Hidden test GT, missing calibration, nonfinite values, duplicate timestamps, and non-monotonic timestamps are excluded. Every directed `map_sequence_i -> query_sequence_j` pair with `i != j` is evaluated, yielding 812 directed candidates for 29 eligible sequences.

The thresholds cannot be lowered:

```text
GT_RESAMPLE_RATE_HZ = 1.0
GT_OVERLAP_RADIUS_M = 5.0
MIN_CONTIGUOUS_COVERED_DURATION_S = 5.0
MIN_TOTAL_COVERED_DURATION_S = 150.0
MIN_COVERAGE_FRACTION = 0.60
MIN_ELIGIBLE_NONOVERLAPPING_5S_INTERVALS = 30
MAX_NATIVE_REFERENCE_GAP_S = 0.20
```

LiDAR point clouds, weather labels, ICP output, registration residuals, map quality, weak/rich geometry, and map visualization/manual inspection cannot be used to select a pair.

Only pairs satisfying every threshold are ranked, in this exact order:

1. `covered_duration_s`, descending;
2. `coverage_fraction`, descending;
3. `eligible_nonoverlapping_5s_intervals`, descending;
4. `nearest_distance_q95_m`, ascending;
5. `map_sequence_id`, lexicographic ascending;
6. `query_sequence_id`, lexicographic ascending.

The first three eligible pairs are frozen as `PRIMARY_PAIR`, `RESERVE_PAIR_1`, and `RESERVE_PAIR_2`.

A reserve may be activated only for an infrastructure failure: a permanently missing download object, checksum mismatch, file corruption, GT-file corruption, or official withdrawal of a primary-pair object. A reserve cannot be activated because ICP error is large, weak/rich results are unfavorable, Open3D and PCL disagree, a correlation is insignificant, or a publication result is unfavorable.
